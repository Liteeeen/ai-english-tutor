# AI 英语朋友 · 技术文档

> 第九届传智杯 · AI 创新应用挑战赛（个人赛）
> 作者：李天恩（马鞍山学院，软件工程大一）

## 一、我为什么做这个

说实话，我英语挺一般的，尤其是「说」。考试还能应付，但真让我开口，脑子就一片空白。而且我发现不光是我，周围很多同学都是这样——这就是大家常说的「哑巴英语」。

所以我就想，能不能做一个**陪我练英语的东西**。它不能像背单词软件那么冷冰冰，最好能像一个朋友：我学得进去的时候教我，我想聊天的时候陪我聊，我哪天累了、emo 了，它也能听我说两句。

后来我把它做成了一个「三位一体」的 AI 英语朋友——**英语老师、英国朋友、心理委员**，它自己会看情况切换。

说句实在的，我大一，编程基本是零基础，Python 都是这个比赛才开始认真学的。这个东西能做出来，有一大半功劳要算到 AI 头上（这也是我参赛想表达的东西：**不会写代码的人，靠 AI 也能做出点东西来**）。

## 二、需求分析

我先把自己当用户，列了一下「我到底需要什么」：

| 功能 | 为什么需要 |
| --- | --- |
| 改语法、翻译、讲句子、查单词 | 这是我学英语最常用的几件事 |
| 出题、做题、批改 | 光学不练记不住，得做点题 |
| 错题本 | 做错的题老忘，得有个地方收着，回头再刷 |
| 学习日历 | 想看看自己坚持了几天，顺便算算离四级还有多久 |
| 历史记录 | 想回头看看自己一路的练习 |
| 能聊天、能安慰人 | 这是我最想要的——学习也能有温度 |

除了这些功能，还有几条「底线」我得守住：

1. **不能动不动就崩**：网络断了、key 错了、超时了，得给个能看懂的提示，别让用户一脸懵；
2. **不能泄露隐私**：API key 不能写死在代码里，聊天记录、错题本这些也不能传上公开仓库；
3. **没装的东西不能卡死整个软件**：语音、头像这些属于「加分项」，不装也得能正常用别的功能。

## 三、系统架构（画个大概）

整体其实就一层一层往上搭：

```
浏览器（Streamlit 界面）
      ↓
app.py（一个文件搞定所有逻辑）
      ↓
DeepSeek 大模型（负责所有「AI 脑力活」）
      ↓
本地 JSON 文件（存历史、错题本、聊天记录）
```

我特意把东西都写在一个 `app.py` 里，没搞什么复杂的框架。一是因为我菜，二是这个规模也真用不着。全在一个文件里，改起来反而清楚。

**界面切换**这块我做了个「窗口栈」：点左上角 ☰ 菜单进某个界面，它就入栈；打开的界面数到 3 个了，就自动关掉最早那个。灵感其实就是 mac 那种窗口管理，觉得挺好玩的就做了。

**状态管理**用的是 Streamlit 的 `st.session_state`。需要跨刷新保留的（历史、错题本、聊天）就额外写到本地 JSON 文件里，这样关掉浏览器再开也不丢。

## 四、AI 这块是怎么做的

### 4.1 为什么选 DeepSeek

我对比过几个：

- **GPT 系列**：能力是强，但贵，还得想办法访问，我一个学生顶不住；
- **DeepSeek**：中文好、便宜、接口跟 OpenAI 兼容，文档也清楚；
- **通义千问**：也不错，但没 DeepSeek 顺手。

最后选了 DeepSeek 的 `deepseek-chat`。便宜对我来说很重要——毕竟预算就那几十块（笑）。

### 4.2 怎么接进来的

用的是 OpenAI 的 SDK，只是把地址指向 DeepSeek：

```python
client = OpenAI(
    api_key=api_key,
    base_url="https://api.deepseek.com",   # 指到 DeepSeek
    timeout=60,
    max_retries=0,
    default_headers={"Accept-Encoding": "gzip, deflate"},  # 这个坑下面说
)
```

### 4.3 让 AI「懂你」：动态 Prompt

这个是我觉得最有意思的部分。我想让 AI 根据我的状态换语气，但又不想再训一个模型（也训不起）。最后想到的办法是——**用规则猜我的状态，再动态拼一段 system prompt 塞给 AI**。

具体就是两条规则：

1. **猜语言**：数一下消息里中文和英文各有多少，判断我是「中文为主 / 英语为主 / 中英混用」；
2. **猜心情**：扫一遍有没有「累、烦、难过」这种词，或者「哈哈、开心」这种词，再数数感叹号，判断我是「低落 / 积极 / 平静」。

然后根据猜出来的结果，给 AI 一段不一样的指令。比如我心情低落，就让它「先像心理委员一样安慰，别急着教知识」；我心情好，就让它「活泼点，可以给点小挑战」。

**这一套东西没花一分钱**，全是几十行规则，但效果出奇地好——AI 真的会「看人下菜碟」了。

### 4.4 遇到的一个坑（brotli）

开发中途有个 Bug 卡了我半天：流式回复一直报 `TypeError: process() takes no keyword arguments`。

查了半天（准确说是让 AI 帮我查了半天），发现是 `httpx 2.x` 的解压器和本地 `brotli` 库版本对不上，压缩数据解不开。最后修法很简单——**在请求头里禁用 brotli，改用 gzip**：

```python
default_headers={"Accept-Encoding": "gzip, deflate"}
```

就这一行，问题解决了。这件事让我特别有感触：**Bug 不一定是你的错，但一定得会查**。而查的过程，AI 帮了我大忙。

### 4.5 一些小优化

- **流式输出**：让 AI 一个字一个字往外蹦，像打字机，等待感没那么强；
- **客户端缓存**：`@st.cache_resource` 缓存客户端，不用每次点按钮都重新连一次；
- **超时控制**：设了 60 秒超时、不自动重试，再配合统一的异常处理，避免「一直转圈」；
- **限长**：单次输入限 5000 字，历史记录留最近 50 条，省 token。

## 五、核心功能怎么实现的

### 5.1 主界面：AI 对话

`render_chat()` 这个函数管主界面。发消息的流程是：先更新我的画像 → 再拼动态 prompt → 最后流式输出。界面用 `st.chat_message` 显示气泡，还能上传图片当 AI 头像。

### 5.2 学习闭环（我觉得是灵魂）

这是我最得意的设计——一条龙：

```
改错 → 点「针对这句话出题」→ AI 出 3 道填空题
→ 我做 → AI 批改 → 做错的自动进错题本 → 重做 → 答对自动删掉
```

批改结果的解析，我让 AI 在回复末尾固定输出一行 `判定：1对 2错 3错`，然后用正则把它抠出来，就知道哪题错了、该不该进错题本。这个方法不算优雅，但简单可靠。

### 5.3 学习日历

用 Python 自带的 `calendar` 模块画月历，标出「今天」和「坚持的日子」，再算算离四级（2026-12-12）还有几天。没用什么花哨的库，够用就行。

### 5.4 语音输入（可选）

用 `streamlit-mic-recorder` 录音，发给 Azure Speech 识别成文字，可以改了再发。这个功能是「可选依赖」，没装或者没配 Azure key 的时候，会自动降级、提示一下，不影响别的功能。

### 5.5 AI 生成头像（可选）

用阿里云百炼的「通义万相」文生图，输入一段描述就能生成一个原创的二次元头像。调用方式是「异步提交任务 + 轮询等结果」，这个流程是照着阿里云的文档一点点调的。

## 七、创新点（我自己觉得）

**技术上的：**

1. 用「规则猜状态 + 动态 Prompt」实现个性化，不用多训一个模型，便宜又可控；
2. 一个模型靠 Prompt 切换三种身份，而不是搞三个模型或者三个 Agent；
3. 学习闭环自动化，从改错到错题本一条龙，不用用户手动整理。

**应用上的：**

1. 把「学习工具」做成「学习伙伴」，兼顾学习和情绪；
2. 这个东西是我一个零基础的大一学生靠 AI 做出来的——这本身就是「AI 赋能」的活例子；
3. 隐私上比较克制：key 不落盘、数据不进库。
